# Architecture Orchestrator

This skill orchestrates a multi-step architecture onboarding workflow for the repository.
It ensures the codebase knowledge acquisition step runs first, then a security assessment, then uses those outputs to drive architecture blueprint generation and LikeC4 architecture-as-code creation.

## Workflow

1. Run `acquire-codebase-knowledge` first.
   - This is the required source-of-truth step.
   - Its output is used as input for the other skills.

2. Run `security-review` after acquisition completes.
   - Performs a full security assessment of the codebase to identify vulnerabilities, exposed secrets, insecure dependencies, weak cryptography, and access-control issues.
   - Writes its findings to `docs/codebase/SECURITY.md` within the scanned repository (overwriting any prior report) and also renders the report inline.
   - Must run before the parallel step below so that any blocking security concerns are surfaced before further architecture work.

3. After security review completes, run the following in parallel if possible:
   - `architecture-blueprint-generator`
   - `likec4-dsl` — use this skill to **create new LikeC4 diagrams** (`.c4`/`.likec4` files) when none exist in the repository (typically under `docs/codebase/likec4/`). After generating or updating diagrams, **validate them using the LikeC4 CLI** (e.g. `likec4 validate`) and resolve any reported errors before completing the step. Once validation succeeds, **render each LikeC4 view as a PNG image** using the LikeC4 CLI (e.g. `likec4 export png <source> -o docs/codebase/likec4/diagrams/`).

4. Validate the required docs exist in `docs/codebase/` after the acquire and security-review steps:
   - `STACK.md`
   - `STRUCTURE.md`
   - `ARCHITECTURE.md`
   - `CONVENTIONS.md`
   - `INTEGRATIONS.md`
   - `TESTING.md`
   - `CONCERNS.md`
   - `SECURITY.md` (produced by `security-review`)

5. **Lint all generated Markdown** before finalising output. This applies to the Architecture Blueprint markdown produced by `architecture-blueprint-generator`, the `SECURITY.md` produced by `security-review`, and every markdown file generated by `acquire-codebase-knowledge` (the seven files listed in step 4).
   - Run `markdownlint` against the generated files using the project config at `architecture-compliance-agent/scripts/config/markdownlint.yaml`.
   - Example: `npx markdownlint-cli2 --config architecture-compliance-agent/scripts/config/markdownlint.yaml "docs/codebase/**/*.md" "Project_Architecture_Blueprint_*.md"`.
   - Fix all reported violations (or use `markdownlint --fix` where safe) and re-run the linter until it passes cleanly. Output is not considered final until linting succeeds.

## Output Contract

The workflow is complete only when:

- `acquire-codebase-knowledge` has run successfully.
- `security-review` has run after acquisition and produced `docs/codebase/SECURITY.md`.
- `architecture-blueprint-generator` and `likec4-dsl` have run after the security review.
- `docs/codebase/STACK.md`, `docs/codebase/STRUCTURE.md`, `docs/codebase/ARCHITECTURE.md`, `docs/codebase/CONVENTIONS.md`, `docs/codebase/INTEGRATIONS.md`, `docs/codebase/TESTING.md`, `docs/codebase/CONCERNS.md`, and `docs/codebase/SECURITY.md` all exist.
- Any missing files are either created by the acquisition step or replaced with a placeholder containing `[TODO]` and/or `[ASK USER]`.
- All generated markdown (Architecture Blueprint + the eight `docs/codebase/` files, including `SECURITY.md`) passes `markdownlint` using `architecture-compliance-agent/scripts/config/markdownlint.yaml` with no errors.

## Validation Checklist

- [ ] Acquire codebase knowledge first.
- [ ] Run `security-review` after acquisition and confirm `docs/codebase/SECURITY.md` is written.
- [ ] Run architecture blueprint generation after the security review.
- [ ] Run LikeC4 DSL creation after the security review; generate new `.c4`/`.likec4` diagrams if none exist and validate them with the LikeC4 CLI.
- [ ] Render all LikeC4 views as PNG files using the LikeC4 CLI and store them under `docs/codebase/likec4/diagrams/`.
- [ ] Confirm all eight required docs exist in `docs/codebase/` (including `SECURITY.md`).
- [ ] Recover any missing docs with placeholders or explicit questions.
- [ ] Lint the Architecture Blueprint and all eight `docs/codebase/` markdown files with `markdownlint` using `architecture-compliance-agent/scripts/config/markdownlint.yaml`; fix violations and confirm a clean pass.
- [ ] Summarize findings, evidence, and any `[ASK USER]` items.

## Notes

- `security-review` runs as a dedicated step between `acquire-codebase-knowledge` and the parallel architecture/LikeC4 step, so security findings are surfaced before any architecture artifacts are produced.
- `architecture-blueprint-generator` and `likec4-dsl` are independent once codebase knowledge and the security review are available, so they can run in parallel when it makes sense.
- The orchestrator validates the required docs in `docs/codebase/` only.
- Prefer evidence-based claims and avoid assumptions when generating architecture or documentation artifacts.
